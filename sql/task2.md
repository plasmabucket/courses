# Реляционные базы данных

#### 2.5) Взаимосвязи между таблицами

1) Отношения "один к одному".  
Одно значение из первой таблицы соответствует только одному значению из второй таблицы, и наоборот.
```
Territories -> EmployeeTerritories  
(К одной TerritoryID привязан только один EmployeeID)
```

2) Отношения "один ко многим".  
Одно значение из первой таблицы может соответствовать многим значениям второй таблицы. Одно значение из второй таблицы соответствует только одному значению из первой.
```
Customers ->> Orders  
Employees ->> Orders  
Shippers ->> Orders  

Region ->> Territories

Categories ->> Products  
Suppliers ->> Products  

Orders ->> Order Details  
Products ->> Order Details  

Employees ->> EmployeeTerritories  

Employees ->> Employees  
(Один EmployeeID может быть указан у многих других сотрудников в колонке ReportsTo)
```

3) Отношения "многие ко многим".  
Одно значение из первой таблицы может соответствовать многим значениям из второй таблицы. Одно значение из второй таблицы может соответствовать многим значениям из первой.
```
Customers <-> Employees  
Customers <-> Shippers  
Shippers <-> Employees  
Эти таблицы связаны между собой таблицей Orders.

Categories <-> Suppliers  
Эти таблицы связаны между собой таблицей Products.

Orders <-> Products  
Эти таблицы связаны между собой таблицей Order Details.
```
